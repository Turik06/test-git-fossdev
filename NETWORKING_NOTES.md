# Заметки по сетевому взаимодействию в Docker
## 1. Локальный запуск (127.0.0.1)
При запуске сервисов напрямую, адрес `127.0.0.1` указывает на общую петлю обратной связи компьютера. Сервисы могут обращаться друг к другу по портам, так как они находятся в одном сетевом пространстве.

## 2. Неудачный запуск в контейнере с 127.0.0.1
В ходе эксперимента в `order-service` был указан адрес `http://127.0.0.1:8000` для связи с `product-service`. 
**Результат:** Ошибка 404.
**Причина:** Внутри Docker каждый контейнер имеет свой изолированный сетевой стек. Для `order-service` адрес `127.0.0.1` это он сам.

## 3. Ошибка конфигурации (Отсутствие переменной)
Здесь проверяется, как система реагирует на отсутствие необходимых настроек в окружении.

**Эксперимент:**
Из файла `docker-compose.yml` была удалена переменная окружения `DISCOUNT_SERVICE_URL`.

**Результат:**
Ошибка **503 Service Unavailable**.

**Причина:**
В коде `order-service` не был явно задан корректный адрес сервиса скидок. Приложение попыталось использовать значение по умолчанию, но внутри контейнера по этому адресу никого нет.

## 4. Успешное взаимодействие через имена сервисов
В `docker-compose.yml` сервисы объединены в общую сеть `service-net`. 
**Результат:** Сервисы успешно общаются по адресам вида `http://product-service:8000`.
**Причина:** Docker Compose использует встроенный DNS. Когда один контейнер запрашивает хост `product-service`, Docker автоматически преобразует это имя во внутренний IP-адрес нужного контейнера.

## 5. Взаимодействие через host.docker.internal
Если бы нам потребовалось обратиться из контейнера к приложению, запущенному прямо на Windows, мы бы использовали адрес `host.docker.internal`. Это специальный DNS-запись, которую Docker прописывает для доступа к localhost хостовой машины.

# Микросервисная система обработки заказов

Данный проект представляет собой учебную реализацию микросервисной архитектуры. Основная цель работы это продемонстрировать контейнеризацию приложений на FastAPI и их взаимодействие в Docker.

## Логика и архитектура 

Система разделена на три сервиса, каждый из которых отвечает за свою логику:

1.  **`product-service`**: Хранит данные о наименованиях и ценах.
2.  **`discount-service`**: Проверяет промокоды и рассчитывает процент скидки.
3.  **`order-service`**: Принимает запрос от пользователя, опрашивает два других сервиса и формирует итоговый расчет заказа.

**Схема работы:**
Запрос пользователя → `order-service` → (запрос цены) → `product-service` → (запрос скидки) → `discount-service` → Итоговый ответ пользователю.

## Сетевое взаимодействие:

* **Docker Network**: Все сервисы объединены в общую сеть `service-net`.
* **DNS-имена**:Сервисы находят друг друга по именам, заданным в `docker-compose.yaml`.
* **Переменные окружения**: Все URL-адреса зависимостей передаются через `environment`. Это позволяет запускать один и тот же код и локально, и в Docker, просто меняя настройки в одном файле.

## Makefile

Согласно требованиям к автоматизации рутинных задач, базовое управление проектом осуществляется через `Makefile`. С его помощью была автоматически сгенерирована файловая структура и директории проекта.

Основные таргеты:
* `make create-structure` — генерация файловой системы (создание папок `src`, `test`, `docs`, файлов документации и заглушек `.gitkeep`).
* `make install-dep` — быстрая установка зависимостей.
* `make run-product` / `make run-order` — скрипты для локального запуска микросервисов
* `make test-pytest` — запуск системы тестирования.
